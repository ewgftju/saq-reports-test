# Подключение рабочих данных

## Контракт текущего макета

`engine.generate(records, config)` принимает нормализованные записи и конфигурацию. `config` содержит `sources`, `filters`, `columns`, `group`, `name`, `template`. Результат содержит строки, перечень колонок, параметры, дату формирования, число записей и уникальных объектов. Это локальный контракт макета, а не существующий API модулей.

В рабочем модуле нужен серверный сервис формирования. Клиент отправляет конфигурацию, сервер проверяет допустимые поля и права пользователя, читает согласованную версию данных и возвращает результат либо идентификатор фонового задания. Экспорт должен строиться по тому же снимку, что и предпросмотр. Ограничения доступа нельзя доверять клиентским фильтрам.

## Единицы учета

| Источник | Ключ и единица | Основные данные |
| --- | --- | --- |
| СУР | risk_assessment_id + версия расчета + объект | Балл, уровень риска, период, отбор |
| ВГА | case_id; отдельно audit_object_id | Дело, объект, охват, отчетная дата, нарушения |
| СВА | case_id; отдельно audit_object_id | Мероприятие, объекты, результаты, исполнение |
| ПРОФ | control_case_id + object_id | Акт результатов, предписания, подтвержденные меры |
| Возражения | objection_id; пункты отдельно | Связанное дело/акт, оспоренный пункт, решение |

Демо использует одну строку на запись модуля с одним объектом. Рабочие данные требуют отдельных фактов: дела, объекты, нарушения, исполнение, санкции и бюджетные программы. Плоское объединение этих таблиц до суммирования приведет к повторному учету. Сначала агрегировать каждую таблицу на нужном уровне, затем соединять по явным ключам. Уникальный ключ записи макета — `(module, id)`, уникальный объект — БИН.

## Привязка полей исходных форм

Четыре схемы и полный путь каждого заголовка находятся в `templates.js`. Начальное сопоставление демонстрационных полей находится в `engine.templateMapping()`. Для рабочей реализации создать версионируемый каталог показателей: код, подпись, единица, модуль, документ/поле, ключ факта, дата учета, формула, допустимая агрегация, правило пустого значения, дата начала действия.

Требуют согласования: классификатор нарушений по разделам/главам/принципам; бюджетные средства и активы; закупочные процедуры и лоты; восстановление/возмещение/отражение по учету; рекомендации; передачи материалов; административные и дисциплинарные взыскания. Часть этих источников может находиться за пределами пяти модулей. Наличие формы само по себе не означает наличие всех показателей в системе.

Форма АБП должна формироваться на уровне объекта риска, АБП, программы и подпрограммы, с распределением денежных сумм по этому уровню. Демо имеет один АБП и одну программу на запись. Исходный пример 30301 содержит несколько строк одного дела: суммировать повторяющийся охват дела в каждой строке нельзя.

ЭГА рассматривается как электронный формат ВГА в соответствии с архитектурой SAQ. Перед рабочим подключением подтвердить признаки отбора с владельцем формы. Свод по органам в демо использует дела ВГА, как указано в исходном заголовке «Количество дел ВГА»; добавление СВА и ПРОФ в официальный свод требует отдельной методики.

## Периоды и итоги

- В демо период — отчетная дата включительно. Период охвата аудита, дата утверждения и дата исполнения являются отдельными измерениями.
- Просрочка — незавершенная запись со сроком ранее конца выбранного периода. Рабочее восстановление исторического статуса потребует истории событий; текущий статус не доказывает статус в прошлом.
- Денежные значения: тысячи тенге. Для рабочего сервиса использовать decimal, округление на выходе по согласованной точности.
- Балл риска — среднее по выбранным расчетам. Финансовые показатели неприменимы к СУР и возражениям.
- Возражения не увеличивают сумму нарушений; окончательное решение должно изменять согласованную версию нарушения. Нельзя одновременно суммировать исходную и скорректированную версии.
- Процент устранения — сумма подтвержденных мер / сумма, подлежащая устранению. При нулевом или отсутствующем знаменателе значение отсутствует.
- Суммирование уникальных объектов по модулям недопустимо: один БИН может встречаться в разных модулях.

## Приемка интеграции

Сверить с владельцем отчета закрытый контрольный период по каждой форме. Проверить отдельное дело с несколькими объектами и программами, несколько нарушений и исполнений одного предписания, возражение с частичной отменой, записи на границе периода, нулевые/отсутствующие значения и права территориальных пользователей. Итоги предпросмотра и выгрузки должны совпадать на одном снимке.
